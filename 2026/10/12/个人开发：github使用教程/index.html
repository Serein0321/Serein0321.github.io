个人使用 GitHub 进行开发教程

先认识几个词

名称 一句话解释
Repository 保存项目文件和修改历史的仓库。
Clone 把远程仓库和历史克隆到电脑。
Branch 指向某次提交的可移动标签，用来分开开发。
Commit 将暂存区的修改保存为一次本地提交。
Push 把本地提交上传到远程仓库。
Fetch 获取远程更新，暂时不合并到当前分支。
Pull 获取远程更新，再整合进当前分支。
Pull Request（PR） 提出修改，请求把一个分支合并到另一个分支。
Merge 把一个分支的修改合并进当前分支。
Fork 在自己的 GitHub 账号下创建别人的仓库副本。

git pull 是拉取远程更新，Pull Request 是请求合并，两者不是同一个操作。

六、创建自己的分支

分支让新功能和稳定版本分开，开发完成后再合并回 main。

git switch -c 同时创建并切换分支，git branch 前面的 * 表示当前分支。

新分支刚创建时和主分支指向同一条提交；创建新的 Commit 后，两条分支才会出现不同内容。

九、使用 Pull Request 合并分支

PR 是“请把我的功能分支合并进主分支”，它会保留修改说明、讨论和检查记录。

即使只有一个账号，也可以自己创建 PR、检查修改并合并；自己的 PR 不能给自己提交 Approve 审查。

本节假设第七节的功能分支已经推送，但还没有按第八节合并。

创建 PR

打开 GitHub 仓库，点击 Compare & pull request；没有提示时，进入 Pull requests → New pull request。

确认合并方向：

填写标题和说明，再点击 Create pull request；还没写完时，可以创建 Draft PR。

说明写清两件事即可：改了什么，以及检查了什么；没运行测试就不要写“测试通过”。

检查 PR

重点检查有没有误删文件、提交敏感信息，以及本次修改是否符合目标。

Merge PR 是什么意思

Merge PR 就是接受这个 PR，把修改合并到选定的目标分支。

确认修改正确、必要检查通过且没有未解决冲突，再点击 Merge pull request → Confirm merge。

按钮不能点击时，先看页面提示，可能需要解决冲突、等待检查或满足分支保护规则。

合并方式 区别
Create a merge commit 保留分支上的提交，并新增一条合并提交。
Squash and merge 将本次 PR 的修改合成一条新提交。
Rebase and merge 将提交依次接到目标分支后面，提交编号会变化。

刚开始可以选择仓库允许的普通 Merge，不必同时练习所有方式。

Close pull request 只是关闭请求，没有把修改合并到主分支。

PR 操作参见 GitHub 创建 Pull Request。

十五、和朋友协作开发

有仓库写入权限时，双方克隆同一个仓库，各自在自己的分支开发。

仓库负责人进入 Settings → Collaborators → Add people 邀请朋友，朋友接受邀请后再推送代码。

朋友先同步 main，创建自己的功能分支，修改后 Commit、Push，再提交 PR。

负责人检查 Files changed 和测试结果，有问题就留言，朋友继续在同一分支提交修改。

审查选项中，Comment 是留言，Approve 是同意，Request changes 是要求修改。

确认可以合并后由有权限的人合并，双方再拉取最新 main，不要直接覆盖对方的文件。

Fork 和 Clone 不会让你获得原仓库的写入权限，是否接受修改由原项目维护者决定。

十七、记录任务和发布版本

功能 用途
Issues 记录 Bug、功能需求和待办任务。
Labels 给 Issue 和 PR 分类，例如 bug、documentation。
Milestones 将一组任务归到同一个版本目标。
Projects 用看板整理待办、进行中和已完成的任务。
Tags 给某条提交标记版本号。
Releases 基于 Tag 发布版本说明和下载附件。

在仓库的 Issues → New issue 创建任务，写清目标和完成条件。

修复同仓库的 Issue 时，可在 PR 说明里写 Closes #1；合并到默认分支后会关闭对应 Issue，1 换成实际编号。

准备发布时，先切到最新主分支，确认代码和测试无误，再标记版本：

版本号要选一个尚未使用的值；不要重复执行命令来覆盖已有版本。

随后在 GitHub 的 Releases 中创建发布，选择这个 Tag、填写版本说明，按需要上传安装包。

Tag 不等于安装包，上传 Tag 也不会自动替项目编译程序。

README 写清项目用途和使用方法；LICENSE 用于说明许可，没有许可文件不代表可以任意使用代码。

十九、常见问题

Push 返回 403

先确认 git remote -v 指向自己的仓库，再检查当前登录账号是否有写入权限；设置 user.name 不会增加权限。

Push 被拒绝：non-fast-forward

远程有本地尚未包含的提交，先保存自己的改动，执行 git fetch origin 检查历史，再按需要合并或 Rebase。

本文的 --ff-only 遇到分叉会停止，不要把停止当作需要强制 Push 的理由。

PR 提示没有共同历史

功能分支和主分支不是从同一套历史分出来的，可能是重新 git init 或创建了孤立分支。

先备份自己的修改，再从正确的 origin/main 创建新分支，把需要的改动重新提交；不要直接强行合并无关历史。

明明修改了，Commit 却没内容

检查文件是否保存，执行 git status，确认需要的修改已经 git add 到暂存区。

Push 成功，主分支却没变化

可能只上传了功能分支，先切换 GitHub 网页的分支查看，再通过 Merge 或 PR 合并到 main。

切换分支时提示本地修改会被覆盖

先 Commit、Stash 或备份改动，再切换分支，不要直接强制丢弃。

二十、命令速查

命令 作用
git status 查看分支和文件状态。
git diff 查看未暂存的改动。
git diff --staged 查看本次准备提交的改动。
git add 文件名 暂存文件的改动。
git commit -m "说明" 创建本地提交。
git push 上传当前已配置对应关系的分支。
git fetch origin 获取远程更新，不合并当前分支。
git pull --ff-only origin main 快进同步当前的主分支。
git switch -c 分支名 创建并切换分支。
git switch 分支名 切换已有分支。
git branch -a 查看本地和远程跟踪分支。
git branch -d 分支名 删除已合并的本地分支。
git merge 分支名 将指定分支合并到当前分支。
git log --oneline --decorate --graph --all -10 查看最近的分支与提交关系。
git remote -v 查看远程仓库地址。

最重要的区别：Add 是准备提交，Commit 是本地存档，Push 是上传，Merge 才是合并。
